## 2024-05-24 - Memoizing Context Values in Next.js
**Learning:** When creating global context providers (like `CartProvider` and `ToastProvider`) in Next.js, passing an unmemoized object literal to `value` (e.g., `value={{ items, itemCount }}`) causes the context value reference to change on every render of the provider. This forces all components consuming the context to re-render, even if the underlying data hasn't changed, creating a cascading performance bottleneck across the application.
**Action:** Always wrap the context `value` object, as well as any expensive derived states (like `itemCount` or `subtotal`), in `useMemo` with appropriate dependency arrays. This ensures the context value reference remains stable across renders unless dependencies actually change.
